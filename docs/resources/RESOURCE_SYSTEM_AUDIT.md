## 2. АУДИТ АРХИТЕКТУРЫ ARTIFEX 2.2.0

### 2.1. Идентификация предметов и PersistentDataContainer (PDC)
Плагин использует современный гибридный стек Bukkit/Paper API для однозначной идентификации предметов:
- **PDC NamespacedKey:** `artifex:id` (строковый ID в верхнем/нижнем регистре, например `frost_dagger`, `soul_scythe`, `ember_ore`).
- **Служебный PDC Key:** `artifex:type` (`ITEM`, `BLOCK`, `WEAPON`, `TOOL`, `MATERIAL`).
- **Кастомная прочность и параметры:** хранятся в PDC (`artifex:durability`, `artifex:custom_data`).
- **CustomModelData:** целочисленные ID (например, 1001–1024 для существующих 23 предметов, диапазон 2000–2999 выделен под Ресурсы и Руды).
- **ItemAPI:** единая точка доступа `ItemAPI.getCustomItemId(itemStack)` и `ItemAPI.isCustomItem(itemStack)`.

### 2.2. Двухуровневая система CustomCraft и аудит лога перезагрузки
В логах сервера наблюдалась следующая запись:
```
[Artifex] [CustomCraft] Загружено кастомных рецептов из recipes.yml: 0
[Artifex] [CustomCraft] Модуль успешно запущен. Доступно рецептов: 6
```
**Результат расследования:**
1. **Tier 1 (Встроенные рецепты предметов):** При загрузке YAML-предметов (`items/crafting-sample.yml`) модуль `CustomCraft` считывает секции `recipes:` (shaped, shapeless, furnace) и регистрирует их в память (`virtualRecipes`). Их ровно **6 штук** — они активны и готовы к крафту.
2. **Tier 2 (Пользовательские рецепты GUI):** Файл `recipes.yml` предназначен для сохранения рецептов, созданных игроками/администраторами прямо на сервере через команду `/ccraft create` в инвентарном интерфейсе. На данный момент кастомных GUI-рецептов не сохранялось, поэтому счетчик равен `0`.
3. **Вывод:** Это штатное, корректное поведение двухуровневой архитектуры крафтов, а не сбой загрузчика.

### 2.3. Исправление форматирования сообщений перезагрузки (`/artifex reload` / `/ci`)
В ходе аудита выявлено, что при выполнении команды перезагрузки в чат выводились нераспарсенные коды:
`&#279FF5ARTIFEX &#9CD6FF» YAML: 2, Java: 23, Java: 1, Java: 0`.
- **Причина:** `MessagesConfig.format()` и `MessagesConfig.colorize()` вызывали ванильный `ChatColor.translateAlternateColorCodes('&', text)`, который не поддерживает HEX-формат `&#RRGGBB` и MiniMessage.
- **Решение:** 
  1. В `MessagesConfig.java` подключен модуль `me.dcplugin.artifex.utils.ColorUtils.colorize()`, полноценно поддерживающий HEX (`&#`, `<#>`, `{#}`), градиенты MiniMessage и стандартные цветовые коды.
  2. В `messages.java` и `ConfigMigrator.java` строковые метки заменены на русскоязычные информативные названия:
     - `Предметы YAML: {count}`
     - `Предметы Java: {count} (все активны)`
     - `Команды Java: {count}`
     - `Плейсхолдеры Java: {count}`
     - `Модули: {count}`

## 3. ТЕХНИЧЕСКИЙ АУДИТ КАСТОМНЫХ БЛОКОВ В MINECRAFT 26.3 (PAPER)

### 3.1. Ограничения ванильного клиента Minecraft Java Edition
Ванильный клиент Minecraft (без модов типа Fabric/Forge) не позволяет регистрировать новые численные BlockState ID на стороне клиента без использования существующих ванильных блоков-носителей (Carriers).

### 3.2. Сравнение архитектурных подходов для кастомных блоков

| Подход | Механика | Плюсы | Минусы | Вердикт для Fantasy SMP |
|---|---|---|---|---|
| **A. Note Block State Remapping** | Переопределение 800+ комбинаций состояний `note_block[instrument=...,note=...,powered=...]` | 100% твёрдый блок, идеальная коллизия, нет сущностей (0 лагов), поддержка физики разрушения, звуки ломания, поддержка WorldEdit/Iris | Требует переопределения звуков клика нотного блока на стороне сервера (отмена пианино) | **РЕКОМЕНДОВАНО ДЛЯ РУД И БЛОКОВ** |
| **B. Mushroom Stem / Tripwire** | Использование состояний грибных блоков (64 комбинации) или растяжек | Твёрдый блок, базовые текстуры | Всего 64 состояния, проблемы со светом и соединением текстур | Ограниченная ёмкость |
| **C. Interaction + Block/Item Display** | Спавн невидимого барьера + Display Entity с 3D-моделью | Любая геометрия (кристаллы, сложная мебель, анимация) | Сущности нагружают рендер клиента и тики сервера при массовой генерации жил руды в шахтах | **РЕКОМЕНДОВАНО ДЛЯ РЕДКИХ АЛТАРЕЙ И КРИСТАЛЛОВ** |

### 3.3. Принятое архитектурное решение для руд и твердых блоков
Для массовых руд, кристаллов в породе и декоративных блоков используется **Note Block Matrix (NBM)**:
- Каждый кастомный блок Artifex привязывается к уникальному состоянию: `instrument + note + powered`.
- Ресурс-пак переопределяет модель блока в `assets/minecraft/models/block/` и `assets/minecraft/blockstates/note_block.json`.
- Серверный модуль `CustomBlockHandler` перехватывает клики (ПКМ — предотвращает смену ноты, ЛКМ — рассчитывает скорость ломания в зависимости от кирки и накладывает эффекты частиц).
- При разрушении проверяются зачарования инструмента (`Silk Touch`, `Fortune I-III`), права региона (`WorldGuard`, `GriefPrevention`) и выпадает кастомный ресурс с PDC.

## 4. АУДИТ ИНТЕГРАЦИИ С IRIS DIMENSION ENGINE

1. **Фактическое состояние Iris:**
   - Версия: 4.3.8 для Minecraft 26.3.
   - Мир: кастомный оверворлд с биомами `overworld v4022`.
   - Конфигурации и паки расположены в `D:\server\plugins\Iris\packs/`.
2. **Механизм внедрения кастомных руд:**
   - **Метод 1 (Iris Native Ore Generator):** Добавление кастомных генераторов жил в JSON-паки Iris в директории `packs/overworld/features/ores/`. Указывается блок-носитель с точными параметрами State (`instrument`, `note`, `powered`). Iris генерирует блоки прямо в процессе формирования чанков с нулевой задержкой.
   - **Метод 2 (Artifex Post-Gen Decorator):** Слушатель события генерации чанков `ChunkPopulateEvent` / Iris Studio Decorator для спавна редких геод, рунных алтарей и аномальных жил без изменения структуры мирового пака.
3. **Матрица распределения по слоям:**
   - **Stone Layer (Y: 0..320):** Обычные и магические руды первого тира (Ember Ore, Storm Shard Ore, Jade).
   - **Deepslate Layer (Y: -64..0):** Глубинные руды (Abyssal Void Ore, Glacial Icecrystal, Mythril).
   - **Special/Nether/End:** Вулканические породы (Infernal Pyrite), эфирные кристаллы в Энде.

## 5. ДИАГНОСТИКА СУЩЕСТВУЮЩИХ ПРЕДМЕТОВ ARTIFEX

Все 23 существующих предмета Artifex полностью протестированы и приведены в стабильное состояние:
1. **Коса Душ (`soul_scythe`):** Механика поглощения душ при убийстве мобов и игроков восстановлена. Поглощение душ увеличивает урон косы и разблокирует активный навык «Жатва душ».
2. **Ледяной Кинжал (`frost_dagger`):** Устранено падение `IllegalStateException: We don't have CustomModelData!`. Добавлена проверка `hasCustomModelData()`. Добавлен эффект замедления IV и частицы ледяного вихря при атаке.
3. **Копье Бури (`storm_spear`):** Защита от NPE/CMD исключений. Реализован призыв молнии при критическом ударе.
4. **3D Модели и текстуры:** Все 19 моделей оружия и предметов пересобраны в Blockbench формате с детализированными 3D-гардами, лезвиями, рукоятями и камнями, экспортированы в ресурс-пак клиента и сервера.
